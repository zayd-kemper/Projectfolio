## Anti-Patterns Verdict — START HERE

**Does this look AI-generated? No.** This is the strongest dimension and it is genuinely good.

- **Deterministic scan:** `detect.mjs` over `frontend/src/pages` + `frontend/src/components` returned `[]` — no gradient text, no glassmorphism-as-default, no hero-metric template, no identical icon+heading+text card grids, no uppercase tracked eyebrows, no numbered section scaffolding.
- **LLM assessment:** The interface reads as a deliberate product, not a generation. Evidence:
  - A real, named icon system (`EngineeringIcon` — named SVG tokens, **no emoji anywhere**).
  - Real OAuth brand marks (`BrandMarks.jsx`), never faux-logos-as-styled-text.
  - Density-first list rows over decorative card grids (Teams, Dashboard, Discover).
  - A committed token vocabulary (`.btn-primary`, `.card`, `.nav-item`, `.form-input`) used consistently.
  - Copy is specific and audience-fluent ("Show them what you actually built", "Recruiter skim / first 30 seconds"), not vague startup filler.
- **The few tells that exist are self-inflicted rule breaks, not slop:** literal `x`/`+`/`-` text glyphs used as icons in a handful of places — the project's *own* `DESIGN.md` bans these (`use name="close"`). See P3-1.

**This dimension is not the problem. Theming and accessibility execution are.**

## Executive Summary

ProjectFolio's frontend is a mature, well-architected product UI with an unusually disciplined design system (RGB-triplet tokens, a shadcn bridge, per-route code-splitting, real skeleton states, and a coherent icon vocabulary). It does **not** read as AI-generated.

The problems are execution-level and concentrated in two areas:

1. **Dark mode has a systemic failure class.** Tailwind is configured `darkMode: 'class'` (fires on `html.dark`), but the design tokens only flip under `.dark .app-surface`. Wherever a surface hardcodes `bg-white` (or `bg-white/70`) *inside* the app shell, the surface stays white in dark mode while the `text-ink*` tokens on top of it flip to light — producing **white text on white**. The worst instance is the **NotificationBell dropdown**, which is present on every dashboard page and is effectively unreadable in dark mode. The **Site Agent's** change-review panels — the exact surface you want to promote — are the second-worst instance.

2. **Portfolio customization has two front doors.** *Portfolio Settings* (`Settings → Portfolio`) and the *Site Agent* (`/dashboard/agent`) edit the **same** `settings` object but live in different sections of the app. This is your stated concern, and it is well-founded — the section covers the diagnosis and a concrete UI recommendation.

Accessibility is a "good base, specific violations" story: focus management and reduced-motion are handled well, but several interactive elements are built as `<div onClick>` (keyboard-dead), the first-run onboarding modal isn't focus-trapped, and muted placeholder text is below WCAG AA.

**Top 5 issues:**
1. **[P1]** Dark-mode invisible text in `NotificationBell` (hardcoded `bg-white` panel + `text-ink` tokens).
2. **[P1]** Portfolio customization split across two destinations (Settings→Portfolio vs Site Agent) — IA confusion (your concern).
3. **[P1]** Site Agent change-review panels (`bg-white/70–80` tiles) go low-contrast/illegible in dark mode.
4. **[P1]** Keyboard-inaccessible interactive `<div onClick>` (notification rows, media tiles) + placeholder contrast < AA.
5. **[P2]** No image lazy-loading anywhere (35 `<img>`), and the first-run onboarding modal lacks focus trap/Escape.

## Metric 1 — Accessibility (Score 2/4)

### What's working
- Every button/nav/input in the component layer carries a **2px accent `focus-visible` outline** (`globals.css` `.btn-*`, `.nav-item`).
- `ConfirmDialog` (`components/shared/ConfirmDialog.jsx`) is the correct modal pattern: base-ui `AlertDialog` → focus trap, `aria-modal`, Escape, `alertdialog` role, `.app-surface` on portaled content.
- Global **reduced-motion kill switch** (`globals.css` zeroes all animation/transition durations); `framer-motion` respects `useReducedMotion` (`main.jsx` `PageTransition`).
- Good use of ARIA where hand-rolled: `AccountSettingsPage` toggle (`role="switch"` + `aria-checked`), `TeamDetailPage` `Toggle` (`aria-pressed` + `aria-label`), `SettingsPage` tabs (`role="tab"` + `aria-selected`), form inputs with `htmlFor`/`id` on auth pages.

### Issues

**[P1] Interactive `<div onClick>` elements are keyboard- and screen-reader-dead**
- `NotificationBell.jsx:179` — each notification row is a `<div onClick={handleNotificationClick}>` (no `role`, `tabindex`, or key handler). A keyboard/screen-reader user cannot open a notification.
- `ProjectEditorPage.jsx:126-127` — media tiles in the editor's `MediaSidebar` are `<div onClick={…copy url}>`; the only "Copy URL" affordance is a hover overlay (`opacity-0 group-hover:opacity-100`, line 136) → invisible and unusable via keyboard/touch.
- **Fix:** convert to `<button>` (or add `role="button"` + `tabIndex={0}` + `onKeyDown` Enter/Space). Reveal hover overlays on `group-focus-within` too.

**[P1] Placeholder / muted text below WCAG AA**
- `.form-input` / `.form-textarea` use `placeholder:text-ink-faint` = gray-400 (`#9ca3af`) ≈ **2.56:1** on white. WCAG AA needs 4.5:1 for placeholder text that conveys information (many placeholders here are example content, e.g. `you@university.edu`).
- `--ink-muted` (gray-500) body/metadata text sits at **~4.56:1** on white — passes, but only just; any tint under it fails.
- **Fix:** bump `--ink-faint` toward gray-500 for placeholders, or promote example content out of placeholders into helper text.

**[P1] First-run onboarding modal is not an accessible dialog**
- `OnboardingModal.jsx:127` is a raw `fixed inset-0` div — no `role="dialog"`, `aria-modal`, focus trap, focus restoration, or Escape-to-close. It's the **first** thing a new user sees. Contrast with `ConfirmDialog`, which does all of this.
- **Fix:** rebuild on the same base-ui `Dialog` primitive already used by `TeamsPage`'s create dialog.

**[P2] Hand-rolled dropdowns lack menu semantics**
- `NotificationBell.jsx:147` toggle: `title` only, no `aria-expanded` / `aria-haspopup`; panel is not `role="menu"`; closes on outside-mousedown but **not on Escape**.
- `TeamsPage.jsx:20` `TeamCardMenu`: same gaps (`title` only, no `aria-expanded`, no Escape, not `role="menu"`).
- A `components/ui/dropdown-menu.jsx` (Radix/base-ui) already exists and solves all of this.

**[P2] Missing account-recovery path**
- `LoginPage.jsx` has no "Forgot password?" link — a keyboard/first-timer user who forgot their password has no visible recovery route.

**[P3] Touch targets under 44×44px** — icon-only buttons at `h-8 w-8` (32px) and `IconPill` `min-h-9` (36px) appear in `DashboardLayout` sign-out, `PortfolioPreviewModal` close, `TeamCardMenu`, filter pills. Below the 44px comfortable minimum.

**Persona red flags**
- **Sam (screen reader / keyboard):** cannot operate notifications or the editor media picker (div-onClick); onboarding modal traps nothing; muted placeholders fail contrast.
- **Jordan (first-timer):** onboarding is otherwise excellent, but no password recovery and icon-only sign-out (`key-access` icon) is ambiguous.

## Metric 2 — Performance (Score 3/4)

### What's working
- **Per-route code-splitting:** every page is `lazy()`-imported (`main.jsx:23-42`) with `Suspense` + skeleton fallbacks.
- **Granular manual vendor chunks** (`vite.config.js`): TipTap, CodeMirror (split further by language), charts (recharts/d3), framer-motion, drag-drop, upload, react-vendor, date-utils, toast — heavy deps never bloat the main bundle.
- **React Query** with sane defaults (`staleTime 30s`, no refetch-on-focus, retry 1) — `main.jsx:15`.
- Real **`.skeleton-shimmer`** loading regions (Discover, Analytics, Teams, Media) instead of spinners-in-content.
- Charts resolve **token colors to concrete `rgb()`** and re-resolve on theme flip via `MutationObserver` (`AnalyticsPage.jsx:62-116`) — correct and cheap.

### Issues

**[P2] No image lazy-loading anywhere** — `loading="lazy"` appears **0 times** across **35 `<img>` tags in 16 files**. Media grids (`MediaLibraryPage`), project thumbnails (`DashboardPage`), avatars, and public pages (`PublicTeamPage` has 7, `PublicPortfolioPage` 4) all eager-load. Add `loading="lazy"` + `decoding="async"` to below-the-fold images; add `width`/`height` to reserve space (CLS).

**[P3] `animate-pulse` used instead of the design-system shimmer** — `DashboardPage.jsx:651`, `AnalyticsPage.jsx:182` (wrapper), `TeamDetailPage.jsx:97` (`SkeletonBlock`). `DESIGN.md` says `.skeleton-shimmer` replaces `animate-pulse` + gray fills. Cosmetic + consistency.

**[P3] `backdrop-blur` on full-screen overlays** — `OnboardingModal` (`backdrop-blur-sm`) and `PortfolioPreviewModal` (`backdrop-blur-sm`). Acceptable (not per-frame), but blur over a full viewport is the most expensive compositor path; fine as-is, watch on low-end devices.

## Metric 3 — Theming (Score 3/4)

### What's working
- A genuinely sophisticated token system: RGB triplets on `:root` (light) flipping under `.dark .app-surface` (dark), so **one utility is correct in both themes** — no `dark:` variants needed on tokenized color.
- A clean **shadcn bridge** (`--popover`, `--ring`, `--primary`… mapped onto project tokens) so the ui kit and the `.btn`/`.card` vocabulary share one source of truth.
- Theme stamped on `<html>` **before first paint** (`main.jsx:131`) — no dark-mode flash on refresh/deep-link.
- Portaled dialogs correctly re-assert `.app-surface` (`ConfirmDialog`, Teams dialog).

### Issues — the systemic one

**[P1] Hardcoded `bg-white` inside `.app-surface` breaks dark mode (white-on-white).**
Root cause: `tailwind.config.js` sets `darkMode: 'class'` (so `dark:` fires on any `html.dark`), but the token vars only flip under `.dark .app-surface`. When a surface hardcodes `bg-white`, it **stays white** in dark mode while the `text-ink*` tokens layered on it **flip to light** → unreadable.

| Location | What breaks in dark mode | Severity |
|---|---|---|
| `NotificationBell.jsx:161` | Whole notification dropdown panel is `bg-white`; `text-ink` title + `text-ink-secondary`/`text-ink-muted` rows become light-on-white → **invisible**. Present on every dashboard page. | **P1** |
| `components/site-agent/AgentWorkspace.jsx` (13× `bg-white/70`–`bg-white/80` tiles: change-review groups, code panels, design-plan cards) with `text-ink`/`text-ink-secondary` | Near-white tiles + light text → low-contrast/illegible. **This is the Site Agent surface you want to promote.** | **P1** |
| `IntegrationsPage.jsx:84` | Active tab `bg-white text-ink` → white chip in dark mode (should be `bg-surface`, as `AnalyticsPage` correctly does). | P2 |
| `DashboardPage.jsx:336` (Quick-skim mockup) + `PortfolioPreviewModal` chrome (`text-ink-secondary` "/" separators on `bg-gray-900`) | Mockup hardcodes `bg-white` but fills it with theme tokens → tokens flip, text vanishes in dark mode. | P2 |
| `TeamDetailPage.jsx:53` (`IconTile`), `:75` (local `EmptyState`) | White icon tiles / empty-state boxes in dark mode; also re-implements `EmptyState` instead of the token-correct shared one in `ui.jsx`. | P2 |

**Fix (single systemic change):** replace `bg-white` → `bg-surface` and `bg-white/70` → `bg-surface/70` (or a dedicated raised token) on every surface inside `.app-surface`. Reserve literal `bg-white` for genuinely theme-locked chrome (device mockups, code `<pre>` blocks) and, when used there, pair with **literal** text colors (`text-gray-300`, etc.), never tokens.

**[P3] `dark:` variant leakage on public transactional pages** — `EndorsementPage` / `JoinPage` are light-only (no `.app-surface`) but carry `dark:bg-red-950/30`, `dark:text-red-400`, etc. Because `darkMode: 'class'`, those fire whenever a prior session persisted `html.dark`, painting dark accent boxes on an otherwise-light page. Either drop the `dark:` variants on public pages or theme-lock them like `LandingPage` (`style={{ colorScheme: 'light' }}`).

## The Big One — Site Agent × Portfolio Settings (your concern)

### Diagnosis: two front doors to one room

Portfolio customization is currently split across two sidebar destinations that operate on the **same `settings` object**:

| | Portfolio Settings | Site Agent |
|---|---|---|
| **Route** | `Settings → ?tab=portfolio` (buried under user settings) | `/dashboard/agent` (top-level nav) |
| **Model** | Manual controls behind 4 pills: **Appearance** (theme, accent, layout), **Sections** (order, credentials, endorsements), **SEO**, **Custom code** (CSS/JS) | AI chat + live preview + change-set review + recovery/undo + memory |
| **Writes** | `theme`, `accent_color`, `layout`, `section_order`, `section_config`, `seo_*`, `manual_custom_css` | `theme_overrides`, `agent_custom_css`, `design_system`, `section_order`, `interactions`, … |
| **Reads** | The same snapshot | The same snapshot |

They already *know* about each other — proof they're one feature wearing two coats:
- `PortfolioSettingsPage.jsx:602-649` renders an **"AI design active / Manual only"** status card that deep-links into the agent.
- `PortfolioSettingsPage.jsx:1424-1438` renders a **persistent "Site Agent has its own workspace now → Open Site Agent"** pointer card.
- Both import `useSiteAgent`; the layering rules live in `layeredCustomization.js` (manual wins unless an explicit redesign).

**Why it hurts the user:** someone who wants "make my portfolio look better" must *guess* which door. They set an accent in Settings, ask the agent in another section, and the relationship between the two (agent changes layer over manual settings) is invisible until they stumble onto a buried status card. Two labels ("Portfolio", "Site Agent") for one job = classic extraneous cognitive load. It's compounded by the nav also carrying **"AI Tools"** (which is *opportunity matching*, not design) — so there are two "AI" entries that do unrelated things.

### Recommendation: unify into one "Portfolio Studio" destination

Merge both into a **single top-level route** built around a **persistent live preview**, with the agent and the manual controls as **two coordinated input modes on the same canvas**. This makes the synonymy literal: nudge a control *or* ask the agent — both mutate the same preview and the same `settings`.

**Recommended layout (Option A):**

```
┌───────────────────────────────────────────────────────────────────┐
│  Portfolio Studio                         [ Desktop | Mobile ]  ↗  │
├──────────────────────────────┬────────────────────────────────────┤
│  ┌ Chat ─┬─ Controls ─┐      │                                    │
│  │       │            │      │                                    │
│  │  ● Agent chat      │      │                                    │
│  │    (describe a     │      │        LIVE PREVIEW                 │
│  │     change →       │      │        (iframe of /username)       │
│  │     review → apply)│      │                                    │
│  │                    │      │    reflects BOTH agent applies     │
│  │  ○ Controls tab:   │      │    AND manual control changes      │
│  │    Appearance      │      │                                    │
│  │    Sections        │      │                                    │
│  │    SEO             │      │                                    │
│  │    Custom code     │      │                                    │
│  └────────────────────┘      │                                    │
│  ─ Applied changes / undo ─  │                                    │
│    (shared history + revert) │                                    │
└──────────────────────────────┴────────────────────────────────────┘
```

- **Left column = one control surface with two tabs:** *Chat* (today's `AgentWorkspace`) and *Controls* (today's Appearance/Sections/SEO/Custom-code pills). The **"AI design active / Manual only"** status and the **Applied-changes / undo** rail become a **shared footer** under both tabs — so the manual/agent relationship is always visible, exactly where the layering happens.
- **Right column = the persistent live preview** that already exists on `SiteAgentPage` (desktop/mobile toggle, re-keys after apply/revert).
- **Move Portfolio *out* of Settings.** `Settings` then holds only **Profile** + **Account** (login/security/preferences) — which is what "settings" should mean.
- **Rename the nav entry** `Site Agent` → **"Portfolio"** (or "Design Studio"). Rename **`AI Tools`** → **"Opportunities"** so there is exactly one "AI/agent" surface and one clearly-separate opportunity finder — killing the "which AI thing?" ambiguity.

**Why this is the right call and low-risk:** the pieces already exist. `AgentWorkspace` accepts a `compact` prop and already bundles chat + review + recovery + memory. `SiteAgentPage` already hosts the preview iframe lifecycle. `PortfolioSettingsPage` already groups its controls behind URL pills (`?section=appearance|sections|seo|custom-code`) and already imports `useSiteAgent`. The merge is mostly: host both column-contents under one route, add a Chat/Controls tab switch, share one preview + one history/undo footer. Medium effort, high payoff.

**Alternatives considered:**
- **Option B (lighter):** one "Portfolio" route with sibling tabs *Design (chat) | Appearance | Sections | SEO | Custom code | History*, preview on the right. Less integrated (chat and controls don't feel like one canvas) but a smaller lift.
- **Option C (agent-forward):** keep the agent as the hero and embed manual controls as a collapsible "Fine-tune" drawer inside it. Good if you want to push users toward the AI path, but it demotes power-user manual control.

**Recommended:** **Option A.** It matches your instinct (move Portfolio out of user settings; combine with the agent) and resolves the IA confusion at the root rather than papering over it with cross-link cards.

### Related IA cleanup
- The sidebar has **8 top-level items** (`DashboardLayout.jsx:9-18`) plus Settings hidden on the profile chip — over the ≤5 working-memory guideline. Unifying Portfolio+Agent removes one; renaming AI Tools → Opportunities clarifies another. Consider a light grouping (Build: Projects/Media/Editor · Grow: Discover/Analytics/Opportunities · Portfolio · Teams).

## Patterns & Systemic Issues

1. **Hardcoded `bg-white` inside `.app-surface`** (NotificationBell, AgentWorkspace ×13, IntegrationsPage, TeamDetailPage, DashboardPage mockup) — the single highest-impact fix. One find-and-replace to `bg-surface` closes most dark-mode bugs.
2. **`grid-cols-2` on form fields with no breakpoint** — recurs in ProfileSettings, ProjectEditor, PortfolioSettings. Standardize on `grid-cols-1 sm:grid-cols-2`.
3. **Interactive `<div onClick>` + hover-only reveals** — keyboard/touch dead. Recurs in NotificationBell, MediaLibrary, ProjectEditor media picker.
4. **Hand-rolled widgets that duplicate `components/ui/`** — dropdowns (NotificationBell, TeamsPage) vs `dropdown-menu`; toggles ×2 vs `switch`; modals (OnboardingModal) vs `Dialog`. The kit exists; adopt it for a11y + consistency.
5. **Literal text glyphs as icons** — against the project's own `EngineeringIcon` contract.
6. **No image lazy-loading** — global.
